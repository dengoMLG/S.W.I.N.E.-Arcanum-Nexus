# Правила для 3D-моделей юнитов (.4d / .dxt)

Выведены на ошибках первой модели (Хряк-Гриль, `d_hryakgrill`) и проверены на оригинальных моделях игры.

## Ошибка 1 — вывернутые грани (из-за неё «пропали текстуры»)

Игра рисует у треугольника только лицевую сторону, изнанка отбрасывается. Лицевая сторона определяется порядком обхода вершин: у оригинальных моделей он один и тот же для всех деталей.

В генераторе Хряк-Гриля часть деталей получилась наизнанку:
- нижний корпус (`Lanctalp`);
- обе гусеницы;
- 15 из 24 деталей корпуса, часть башни и огнемёта.

Всего вывернуто 331 из 1712 треугольников. Игра отбросила верх корпуса, и сквозь него стала видна внутренность: серые внутренние стенки без цвета команды. Поэтому на скриншоте корпус был серым, а башня, бак и детали выглядели нормально.

**Откуда взялось.** В `tools/lib/swine-model-kit.js`:
- `addPrismX` строит боковины призмы с одним обходом, а ленту вокруг них — с противоположным. Для профиля против часовой стрелки боковины смотрят наружу, а лента внутрь, для профиля по часовой — наоборот.
- `buildTrackLoop` разворачивает ленту гусеницы внутрь.
- `verifyNormals` не чинит это, а маскирует: подгоняет обход под нормаль, которая сама может смотреть внутрь.
- Превью генератора рисует обе стороны граней, поэтому ошибки на нём не было видно.

**Правило.** Каждая деталь — замкнутая, и все её грани смотрят наружу. Проверять нужно готовый файл, а не превью генератора:

```
node tools/swine-4d-orient.js check <model.4d>     # должно быть «0 з N граней вивернуто»
node tools/swine-4d-orient.js fix   <model.4d>     # развернуть вывернутое наружу (на месте)
```

Важно: корневой узел `Lanctalp` в моделях игры зеркальный (определитель матрицы −1). Поэтому «наружу» считается только в мировых координатах, после всей цепочки матриц. Инструмент так и делает; знак сверен с `d_normaltank`, `d_hardtank`, `d_mozsar`.

## Ошибка 2 — превью зеркальное

`renderSpec` в наборе инструментов проецирует с `-x`, то есть зеркально относительно игры. Номер «66» в превью читается правильно, а в игре задом наперёд. Надписи и любые несимметричные детали нужно проверять в просмотрщике, который рисует как игра.

## Проверка «как в игре»

```
node tools/swine-view.js <model.4d> out.png --cull 1 [--team yellow] [--mip 3] [--yaw 2.2 --pitch 0.35] [--only Test,Lovegtorony]
```

Просмотрщик:
- читает готовые `.4d` и `.dxt`;
- собирает узлы по матрицам;
- красит шейдером COLORIZE из `shaders/standard.hlsl`;
- с `--cull 1` отбрасывает изнанку, как игра.

Чего не видно в этом рендере, не будет видно и в игре.

## Остальные правила

- **Узлы.** Имена и иерархия как у оригинала нужного класса: `Lanctalp`, `Test`, `Lovegtorony` (башня), `Cso` (ствол), `_Torkolattuz` (вспышка), `_kereso`, `_glow*`, `Chain R 001` / `Chain L 001`. Движок анимирует по именам.
- **Цвет команды.**
  - Альфа текстуры — маска покраски. На крашеных местах альфа 1, на металле, резине и надписях альфа 0.
  - Краска должна быть насыщенной и средней яркости, как у оригиналов: насыщенность около 0.35–0.5, яркость около 0.35–0.5. Серая краска с насыщенностью 0 станет серой у любой команды.
  - У свиней в имени модели обязательно `d_`, иначе берутся кроличьи множители цвета.
- **Текстура.** DXT5 512×512 с полной цепочкой mip-уровней до 1×1, размер файла 349 584 байта. Проверка: `node tools/swine-dxt.js info <file.dxt>`.
- **Гусеницы.** Текстура `lanctalp.tga`, U вдоль ленты: игра прокручивает её смещением U.
- **Иконка и ролик магазина.** Серый фон 124,122,124, танк смотрит влево. Ролик — 200 кадров полного оборота 496×368 (`tools/swine-anif.js`).
